GitHub Copilot を Agent Mode で使うと、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。この作業はローカル マシンでリアルタイムに行われるため、VS Code の Copilot Chat では各ツール呼び出しとファイル編集を進行中に確認できます。差分をインラインでレビューし、個々の変更を承認または拒否できます。また、エディターを離れずに追加のプロンプトを使って会話の方向を調整したり、作業範囲を広げたりできます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして承認する。
- セッションの途中でエージェントに指示し、ハイ コントラストに加えてライト モードの切り替えを追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタム エージェントがハイ コントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加したいとのことです。新しい会話を始めるのではなく、既存のセッションに追加作業を依頼します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。エージェントが確認したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにインラインで表示されます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールして、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
    - 変更を承認するには **Keep** を選択します。
    - 変更を元に戻してエージェントにやり直させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。許可する前に、コマンドの内容を確認してください。

5. エージェントがハイ コントラスト モードを実装し終えるまで待ちます。最後に、変更内容の要約が表示されます。

## エージェントにライト モードを追加するよう指示する

ハイ コントラスト モードができたら、同じ会話にライト モードの切り替えを追加します。同じチャット セッションを続けると、エージェントは前の作業で変更したコンポーネント、スタイル、local storage のパターンなどのコンテキストを保持します。

1. Copilot Chat の入力欄で、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認して、ライト モードを追加します。
3. ハイ コントラスト モードのときと同じように、編集内容を確認して、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合 (例: 好みでない方法で切り替え UI をリファクタリングしようとする場合) は、チャット入力欄の近くにある **Stop** ボタンで停止し、補足プロンプトで意図を伝えます。

> [!TIP]
> 作業中のセッションを方向付けると、最初からやり直すより短時間で済みます。追加プロンプトを使って、変更を簡単にする ("CSS を簡潔にして、重複セレクターではなく CSS 変数を使ってください")、方針を修正する ("3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを統合してください")、作業範囲を広げる ("両方の切り替えにキーボード ショートカットも追加してください") ことができます。

## 作業内容をレビューする

作業をコミットする前に、エージェントが変更したファイル全体を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更ファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが指示したアクセシビリティ パターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定保存など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の Agent Mode を使って、ファイル編集を確認しながら進行中のセッションを監視して方向付けました。個々の変更を承認または拒否し、コンテキストを失わずに追加プロンプトで作業範囲を広げました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または拒否しました。
- 追加プロンプトでセッションの途中から作業の方向を調整しました。
